2.4 Модули и события: объекта, менеджера, формы, общие модули

Цель: понимать, в какой модуль писать код, и уметь сделать так, чтобы правило срабатывало всегда — и когда товар записывает пользователь, и когда код. Время: 1 день. Застрял больше 30 минут — пиши. Git: ветка feature/ch2-t4-moduli-i-sobytiya.

1. Что это, зачем, где найти

Модуль — файл с кодом, привязанный к какому-то месту в конфигурации. Событие — момент, когда платформа сама вызывает твою процедуру: «перед записью», «при открытии формы», «при изменении поля».

Зачем: до сих пор ты вызывал свой код сам, кнопкой в Песочнице. В реальной работе большая часть кода запускается сама — в ответ на действие пользователя или записи из другого кода. Задача программиста — знать, куда положить код, чтобы он сработал в нужный момент.

Четыре вида модулей

Продолжим аналогию со складом:

Модуль В жизни Отвечает за Пример кода
Модуль объекта Правила для каждой карточки Одну конкретную карточку товара или один документ «Цена не может быть отрицательной»
Модуль менеджера Инструкция для кладовщика Весь справочник целиком, а не одну карточку «Найти или создать товар»
Модуль формы Поведение окна Окно, в котором работает пользователь «Выбрал товар — подставь цену»
Общий модуль Общая библиотека Ничего конкретного, используется отовсюду ЦенообразованиеКлиентСервер.РассчитатьСумму

Главное отличие: кто и когда вызывает

Модуль Срабатывает при записи из формы Срабатывает при записи из кода Как вызвать самому
Объекта Да Да Через объект: ТоварОбъект.МояПроцедура()
Формы Да Нет Только из этой же формы
Менеджера — — Справочники.Товары.МояФункция()
Общий — — ИмяМодуля.МояФункция()

Отсюда главное правило задачи: правило, которое должно выполняться всегда, пишется в модуль объекта. Код формы помогает пользователю, но загрузку из Excel или обработку он не остановит.

Где найти в EDT

Модуль Путь в навигаторе
Объекта «Справочники» → «Товары» → правый клик → «Открыть модуль объекта»
Менеджера Там же → «Открыть модуль менеджера»
Формы «Справочники» → «Товары» → «Формы» → форма → вкладка «Модуль» внизу редактора
Общий «Общие» → «Общие модули»

Модули объекта и менеджера всегда выполняются на сервере, директивы &НаСервере в них не пишутся. В модуле формы директива нужна у каждой процедуры.

2. Топ событий и приёмов

Модуль объекта

Событие Когда срабатывает Для чего
ПередЗаписью(Отказ) Перед каждой записью Проверить или доделать данные. Отказ = Истина — запись отменяется
ПриЗаписи(Отказ) Сразу после записи, ссылка уже есть Связанные действия: записать что-то ещё
ОбработкаПроверкиЗаполнения(Отказ, ПроверяемыеРеквизиты) При проверке заполнения: форма вызывает сама, код — только через ПроверитьЗаполнение() Сложные проверки: «в документе есть строки», «количество больше нуля»
ПриКопировании(ОбъектКопирования) При копировании элемента Очистить то, что нельзя копировать

У документа ПередЗаписью имеет больше параметров: (Отказ, РежимЗаписи, РежимПроведения).

Обработчик пишется как процедура с точным именем события. Внутри к своим реквизитам обращаешься напрямую: Цена, Наименование, Товары.

Модуль формы

Событие Когда Для чего
ПриСозданииНаСервере Форма создаётся Заполнить значения по умолчанию, настроить видимость
ПриОткрытии Форма показана пользователю Действия на клиенте при открытии
<Поле>ПриИзменении(Элемент) Пользователь изменил поле Подставить или пересчитать связанные значения
ПередЗаписью / ПослеЗаписи Запись из этой формы Действия, нужные только при работе в окне

В форме к данным обращаешься через Объект: Объект.Цена, Объект.Товары. Текущая строка табличной части: Элементы.Товары.ТекущиеДанные.

Как создать обработчик поля: в редакторе формы выбери элемент → панель «Свойства» → раздел «События» → нужное событие → кнопка создания. EDT сам создаст процедуру в модуле формы.

Модуль менеджера

Экспортные процедуры и функции, которые относятся к виду объекта в целом:

// в модуле менеджера справочника Товары
Функция ЦенаПоУмолчанию() Экспорт
    Возврат 100;
КонецФункции

// вызов из любого серверного кода
Цена = Справочники.Товары.ЦенаПоУмолчанию();

Как вывести ошибку пользователю

Сообщение = Новый СообщениеПользователю;
Сообщение.Текст = "Цена не может быть отрицательной";
Сообщение.Поле = "Цена"; // необязательно: подсветит поле в форме
Сообщение.Сообщить();

Сообщить("...") устарел, EDT выдаёт на него предупреждение. В типовых конфигурациях с БСП то же самое делает ОбщегоНазначенияКлиентСервер.СообщитьПользователю("..."), но в учебном проекте БСП нет.

Обработчики записи в модуле объекта по стандарту 1С:

  • начинаются с проверки ОбменДанными.Загрузка (см. справочник);
  • весь модуль обёрнут в #Если Сервер Или ТолстыйКлиентОбычноеПриложение Или ВнешнееСоединение Тогда ... #КонецЕсли.

3. Ловушки

  1. Код формы не срабатывает при записи из кода. Правило «цена не меньше нуля» в форме не остановит загрузку из Excel. Обязательные правила — в модуль объекта.
  2. Отказ = Истина при записи из кода вызывает исключение. Код, который вызвал Записать(), упадёт с ошибкой «Не удалось записать». Если отказ возможен, вызывающий код оборачивает запись в Попытка ... Исключение.
  3. Не вызывай Записать() внутри ПередЗаписью и ПриЗаписи. Запись снова вызовет событие, и код уйдёт в бесконечный круг. В ПередЗаписью просто меняй реквизиты — они запишутся сами.
  4. ОбработкаПроверкиЗаполнения при записи из кода не вызывается. Это та же ловушка, что в задаче 3. Нужна проверка из кода — вызывай ПроверитьЗаполнение().

4. Практика А (15–30 минут)

А1. Правило в модуле объекта

В модуле объекта справочника «Товары» запрети записывать товар с отрицательной ценой: отказ и сообщение пользователю.

Проверь двумя способами:

  1. В 1С:Предприятии открой товар, поставь цену −1, попробуй записать.
  2. В Песочнице создай товар с ценой −1 кодом и запиши.

Подсказки:

  • Какое событие срабатывает перед каждой записью?
  • Как в модуле объекта обратиться к цене этого же товара?
  • Что увидишь во втором случае и почему это не так, как в первом? Ответ — в ловушке 2.

5. Практика Б — проект

Здесь всё крутится вокруг документа «Приход товара».

Подготовка. В EDT добавь в табличную часть Товары документа колонку Сумма: тип Число, длина 15, точность 2. Выведи её на форму документа.

Б1. Форма документа: помощь пользователю

  1. Пользователь выбрал товар в строке — цена подставилась из справочника.
  2. Изменил количество или цену — сумма пересчиталась через твою ЦенообразованиеКлиентСервер.РассчитатьСумму.

Подсказки:

  • Обработчики создаются на колонках табличной части: Товар, Количество, Цена.
  • Текущая строка — через Элементы.Товары.ТекущиеДанные.
  • Обработчик поля работает на клиенте. Можно ли там прочитать Товар.Цена? Если нет — какая директива нужна для функции, которая получит цену на сервере и не тянет туда всю форму? Ищи в синтакс-помощнике или справочнике конспекта.
  • Пересчёт суммы нужен в трёх местах. Как не писать его трижды?
  • Теперь видно, зачем модуль назывался КлиентСервер: его можно вызывать прямо на клиенте.

Б2. Модуль объекта документа: правила, которые работают всегда

  1. ПередЗаписью: пересчитать Сумма во всех строках. Форма считает сумму при вводе, но документ, созданный кодом, форму не открывает.
  2. ОбработкаПроверкиЗаполнения: документ без строк — ошибка; строка с количеством меньше или равным нулю — ошибка с номером строки.

Подсказки:

  • Какой модуль можно вызывать на сервере, чтобы посчитать сумму той же функцией, что в форме?
  • Номер строки есть у каждой строки табличной части в свойстве НомерСтроки.

Б3. Модуль менеджера: навести порядок

Функции НайтиИлиСоздатьТовар и УстановитьЦену работают только с товарами. По стандарту 1С такие функции хранят в модуле менеджера этого объекта, а не в общем модуле.

  1. Перенеси их в модуль менеджера справочника «Товары».
  2. СоздатьПриходТовара — в модуль менеджера документа «Приход товара».
  3. Исправь вызовы в Песочнице и тестах.
  4. В комментарии к коммиту объясни одной фразой, почему так лучше.

Подсказка: как будет выглядеть вызов, если функция лежит в модуле менеджера? Смотри таблицу «Как вызвать самому».

Б4. Тесты — процедура ТестыМодулейИСобытий() в области Тесты:

Проверка Ожидается
Документ из кода: строка с количеством 2 и ценой 500, сумму не заполняем. После записи Сумма строки 1000
Товар с ценой −1 из кода: запись вызвала исключение Истина
Документ без строк: ПроверитьЗаполнение() Ложь
Документ со строкой с количеством 0: ПроверитьЗаполнение() Ложь
Вызов Справочники.Товары.НайтиИлиСоздатьТовар(...) после переноса работает Истина

Тестовые объекты в конце пометь на удаление.

Коммиты:

  • Правила записи товара и прихода в модулях объектов
  • Форма прихода: подстановка цены и расчёт суммы
  • Функции товаров перенесены в модули менеджеров

На ревью — модули объектов, модуль формы, модули менеджеров и скриншот тестов.

6. Справочник

Порядок событий при записи из формы

  1. Форма: ПередЗаписью (клиент).
  2. Проверка заполнения: ОбработкаПроверкиЗаполнения объекта.
  3. Форма: ПередЗаписьюНаСервере.
  4. Объект: ПередЗаписью.
  5. Запись в базу.
  6. Объект: ПриЗаписи.
  7. Форма: ПриЗаписиНаСервере, ПослеЗаписиНаСервере.
  8. Форма: ПослеЗаписи (клиент).

При записи из кода — только шаги 4–6.

Директивы в модуле формы

Директива Где выполняется Есть ли доступ к форме
&НаКлиенте Клиент Да
&НаСервере Сервер Да, вся форма передаётся на сервер
&НаСервереБезКонтекста Сервер Нет, только переданные параметры. Быстрее

Для «получить цену товара по ссылке» подходит &НаСервереБезКонтекста: форма для этого не нужна.

Свойства общего модуля

Флажок Значит
Сервер Доступен в серверном коде
Клиент (управляемое приложение) Доступен в клиентском коде
Вызов сервера Можно вызвать с клиента, выполнится на сервере
Глобальный Методы вызываются без имени модуля. Новичкам не включать
Привилегированный Выполняется без проверки прав. Только по необходимости

Модуль ЦенообразованиеКлиентСервер — Сервер + Клиент: чистые вычисления без базы, работают везде. РаботаСТоварами — только Сервер: работает с базой.

Загрузка при обмене

В типовых конфигурациях обработчики записи часто начинаются так:

Если ОбменДанными.Загрузка Тогда
    Возврат;
КонецЕсли;

При обмене данными между базами проверки пропускаются: данные уже проверены в базе-источнике. В учебном проекте не нужно, но в типовых встретишь часто.

Попытка и исключение

Попытка
    ТоварОбъект.Записать();
Исключение
    Вывести("Не записан: " + ОписаниеОшибки());
КонецПопытки;

Проверь себя

Вопрос Ответ
Чем модуль объекта отличается от модуля формы? Объекта срабатывает при любой записи, формы — только при работе в окне
Куда писать «цена не может быть отрицательной»? В модуль объекта
Чем модуль менеджера отличается от общего? Менеджер относится к одному виду объектов и вызывается через него, общий — ко всей конфигурации
Почему нельзя вызывать Записать() в ПередЗаписью? Запись снова вызовет событие — бесконечный круг
Что будет при Отказ = Истина, если записывал код? Исключение в вызывающем коде
Почему Товар.Цена нельзя прочитать в &НаКлиенте? На клиенте нет доступа к базе
